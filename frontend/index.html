Mind the Gap — how it all works

The whole project in one paragraph

A robot-arm policy (a vision-language-action network) looks at a table and outputs arm motions. In research before this hackathon we found that its internal activations contain a confident, linearly readable belief about whether the item can fit the carton — and that when the carton is too shallow, the policy proceeds to pack it anyway. This viewer plays validated simulator runs while decoding that belief from the policy's own forward pass, so you can watch knowledge and action diverge — then CONNECT BELIEF TO ACTION shows the same belief, wired as a veto, preventing the hazard. No retraining anywhere.

What you're actually watching

  • The footage is a recorded, validated Isaac-simulator run under exactly the scene and wire condition shown on the label — running the physics live takes ~2 minutes per episode, so the execution is replayed.
  • The Robot trace panel is measured, not scripted. Believes = the frozen probe's readout of the VLA's hidden state, from a real forward pass on the exact camera frame the policy saw at the run's decision point. Plans = the policy's own action command. Executes = the controller's recorded phase at the current timestep, from the run's per-step trace.
  • The timeline moments (grasp, carry-despite-belief, forcing, HOLD) are derived from that trace, not hand-placed. The raw trace JSONs are linked under Engineering details.
  • NATIVE POLICY vs SAFETY WIRE switch between the recorded run of the unmodified policy and the recorded run with the gate connected — same scene, same starts.

The cast

  • The world: a packing table in NVIDIA Isaac Sim. Task: “pack the bottle into the carton.”
  • The robot: an SO-101 arm.
  • The policy: an OpenVLA-class network fine-tuned for this task. Input: the camera image. Output: 7 numbers — dx dy dz droll dpitch dyaw gripper.
  • The two cartons: deep (bottle fits) and shallow (physically cannot hold it — forcing the placement jams the bottle and drops it).

How do you read a robot's mind?

Every forward pass of the network produces hidden states — internal activation vectors at each layer. During prior research we captured those activations and fit a tiny frozen classifier (standardize, then logistic regression — one weight vector and a bias) on a single hidden-state row. It predicts “fits” vs “cannot fit” and has not been touched since: same mean / scale / w / b tonight as in every validation run.

The engine applies that probe to the policy's forward pass on the run's decision frame and returns the logit: positive = “cannot fit”, negative = “fits”, magnitude = confidence. The margins are enormous — around −14 on the deep carton vs +7 on the shallow one. The episodes shown were never used to fit the probe, and Engineering details prints this run's exact logit.

Why this is interesting: the knowledge-action gap

Having the belief is not the same as using it. The action head plans the same packing motion whether the belief says “fits” or “cannot fit”. In the prior research, steering the belief direction did not change behavior, and further fine-tuning failed to wire the belief into the actions. The information is stranded — one linear readout away from the motor commands, but disconnected from them.

So when this robot damages the item, “it didn't know” is the wrong diagnosis. It knew. The knowledge just wasn't connected to behavior. That is the gap the freeze-frame catches: belief decoded, arm still moving toward the carton.

The fix: a safety gate made from the robot's own belief

The same frozen probe, run at the decision step as a GO/HOLD monitor: if it reads “cannot fit”, the gate vetoes the motion — the movement command is zeroed and the arm holds still. One linear layer plus a threshold; zero retraining.

In the validation run before the hackathon: hazardous placement attempts went 4/4 → 0/4 with the gate connected, correct placements stayed 4/4, and the gate's decisions were 10/10 with margins of 7+ logits. That gated run is exactly what SAFETY WIRE plays back.

How it's wired, and what was built when

browser → public proxy (this repo) → private engine on a lab GPU. The engine holds the policy weights, the frozen probe, the recorded runs and their traces; the public repo contains only the UI, the proxy, and the interface contract. No credentials or server addresses live in the repo.

Existed before the hackathon: the policy, the probe, the research findings, and the validated runs' science. Built during the hackathon: this viewer — UI, proxy, trace plumbing, and the thin HTTP wrapper on the server. The split is stated in the README, and the private repo's commit history proves the research predates tonight.

Questions you might be asking

Is the trace panel scripted to match the video?
No — every label is a measured quantity: the belief logit comes from a real forward pass on the run's decision frame, and the Executes row and timeline moments come from the run's per-step controller trace (raw JSON linked under Engineering details).
Is the probe just detecting that the carton looks different?
That was tested: an identical probe trained with shuffled labels — same pipeline, same features — fails to produce the carton-conditional behavior. The specific belief content does the work.
Is this cherry-picked?
The gate's validation was preregistered: 10/10 decisions with 7+ logit margins across held-out episode starts, hazardous attempts 4/4 → 0/4, fit placements unchanged. Both scenes × both wire settings are one click away here.
Why not just train the robot better?
Tried in the prior research: additional fine-tuning at multiple budgets did not wire the belief into behavior. The fix that works is one frozen linear readout — which is the point: the knowledge was already there.
Does it generalize?
The same frozen readout transfers across sibling checkpoints of this policy family. It is anchored to the validated scene layout, though — moving the carton elsewhere degrades the readout. Honest limitation, stated as such.
Why does this matter beyond a demo?
It's a recipe: find a safety-relevant belief inside a policy, freeze a probe on it, and run it as a runtime monitor with veto power — a safety layer extracted from the model itself, with no retraining and sub-second overhead.

Glossary

VLA (vision-language-action model)
A neural network that maps camera images (+ an instruction) directly to robot actions.
Forward pass
One run of the network: image in, action out.
Hidden state
The network's internal activation vectors between layers — what it “thinks” en route to its output.
Linear probe
A tiny frozen classifier (weights + bias) applied to a hidden state to decode information from it. Frozen = never updated after fitting.
Logit
The probe's raw score. Positive → “cannot fit”, negative → “fits”; bigger magnitude → more confident.
GO / HOLD gate (“the wire”)
The probe used as a veto: HOLD zeroes the motion command so the arm stays still; GO passes the plan through unchanged.
Per-step trace
The run's recorded log — one entry per timestep with the controller's phase; it drives the Executes row and the timeline.
Isaac Sim
NVIDIA's robotics simulator, where the scenes, physics, and robot live.
